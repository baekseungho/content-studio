작성: 2026-11-19
상태 갱신: 2026-11-20. A~F 핵심 기능과 G 도움말·복구, H 최종 전달 보호, I 직접 발행한 주소 기록까지 구현했다. 아래 현재 상태표는 기능 구현과 남은 현장 검증을 구분한다. 변경 범위는 ../CHANGES.md의 최신 항목을 참고한다.

다음 우선순위는 8절의 대표 작업을 실제 사용자와 계정에서 검증하고 발견한 불편을 수정하는 것이다. 필요성이 확인될 때의 마감일/작성 예정일 보기는 보류한 선택 기능이다. 회원·계정 분리·결제·운영은 처음부터 별도 범위였으며 SERVICE_ROADMAP.md의 미완료 과제로 남는다. 핵심 기능 구현 완료를 유료 서비스 출시 준비 완료로 해석하지 않는다.

## 1. 제품의 중심

핵심 약속: 사진과 실제 경험만 준비하면, 내 말투로 채널에 맞는 글을 완성하고 빠진 조건까지 확인한다.
첫 대상: 일상·장소 후기와 체험단 글을 반복 작성하는 개인 크리에이터. 개발 지식 없이 이용하는 사람을 기준으로 한다.
새 기능은 입력, 반복 작업, 결과 수정, 실수 중 하나를 실제로 줄일 때 추가한다. 기능 개수와 장식보다 완성까지의 이해 가능성을 우선한다.

## 3. 현재 기능을 새 기능으로 세지 않기

이미 있는 것: 선택한 플랫폼만 생성, 플랫폼별 별도 원고, 한국어·영어, 체험단 조건 검사, 5,000자 상한, 본문 분량 표시와 보완, 줄바꿈 설정, 사진 순서·확대, 글 보관·검색, 복구, 일부 되돌리기, 다크 모드, 진행 단계, 블로그 전달 도우미.

개선할 핵심:
- 긴 두 열 화면에 준비·설정·결과·전달 기능이 동시에 노출된다.
- 글 생성 버튼을 누른 뒤 플랫폼을 선택해 작업 범위가 늦게 정해진다.
- 미리보기와 텍스트 편집을 오가며 사진 위치와 실제 문장을 함께 다듬기 어렵다.
- 업체 안내문을 붙여도 조건을 다른 칸에 다시 정리해야 한다.
- 말투·서식 선택이 많지만 결과의 차이를 선택 전에 파악하기 어렵다.
- 같은 이야기의 여러 채널 결과와 다음 할 일을 한눈에 보기가 어렵다.

이는 코드와 현재 화면 구조에 근거한 제품 가설이다. 실제 처음 사용자 관찰로 확인한다.

## 4. 화면 구조: 한 이야기, 세 작업

상단: 이야기 이름 / 저장 상태 / 필요한 보조 동작.
왼쪽: 새 글 만들기, 내 글. 내 말투·기본 꾸미기는 보조 메뉴. 기존 보관함·올린 글은 내 글 안의 상태 필터로 통합한다.
작업 상단: 준비 → 글 다듬기 → 확인하고 옮기기. 단계는 현재 작업 위치를 바꾸며 자유롭게 왕복한다. 처음부터 다시 입력시키는 강제 설문처럼 만들지 않는다.
중앙: 현재 단계의 주 작업. 우측에는 필요할 때만 자료·꾸미기·조건 패널을 연다.
하단: 현재 단계의 대표 행동 하나. 작은 화면에서는 편집 영역을 가리지 않는 위치를 검증한다.

### 준비
- 글 종류: 일상 후기 / 체험단 후기.
- 사용할 채널을 눈에 보이는 선택칩으로 먼저 선택한다. 선택 범위를 생성 전에 요약한다.
- 사진과 경험 메모만으로 기본 경로를 진행할 수 있다. 장소, 말투 세부값, 폰트 등은 선택 항목이다.
- 카페·맛집 / 여행·숙소 / 제품 / 일상 시작 카드를 제공한다. 예시는 사용자가 쓴 메모를 덮어쓰지 않는다.
- 빈 입력창 앞에서 막히면 실제 정보만 묻는 보조 질문 2~3개를 선택적으로 제공한다. 예: 주문한 메뉴, 가장 좋았던 점, 아쉬운 점.
- 장소 검색은 선택. 동명 지점은 주소를 함께 보여 선택받고 선택한 지점 범위로 자료 찾기를 제한한다. 모호한 검색 결과를 확정 사실로 채우지 않는다.
- 이전에 선택한 말투·꾸미기는 짧은 요약으로 보이고 필요할 때 바꾼다.
- 체험단일 때만 업체 안내와 제공 표시·조건 확인을 노출한다.

### 글 다듬기
- 읽는 화면에서 바로 고치는 블록 편집기를 중심으로 한다. 제목, 소제목, 본문, 사진, 정보, 태그를 구분한다.
- 사진은 문단 사이로 이동하고 키보드용 위/아래 이동도 제공한다. 사용자는 사진 위치 코드를 다루지 않는다.
- 텍스트 선택 또는 문단 메뉴: 더 자연스럽게 / 짧게 / 자세히 / 이 부분만 다시 쓰기. 수정 전후를 보고 적용·취소한다.
- 다른 문단, 사진 배치, 다른 채널 원고를 임의로 바꾸지 않는다.
- 사진·텍스트·서식 수정 모두 되돌리기 대상이다. 큰 생성·변환 전에는 복구 가능한 버전을 남긴다.
- 상단 채널 탭에서 같은 이야기의 다른 채널 글을 관리한다. 추가 채널은 그 채널만 만든다.
- 한국어→영어 전환은 선택한 채널에서 명확하게 실행한다. 기존 원고를 보호하고 새 결과의 언어를 검사한다.
- 줄바꿈·정렬·기본 폰트는 짧은 예시가 있는 꾸미기 패널에 모은다. 단순 정렬·배치 변경에는 글을 재생성하지 않는다.

### 확인하고 옮기기
- 필수 수정 / 직접 확인 / 더 좋아지는 제안으로 나눈다. 취향 제안 때문에 전달을 차단하지 않는다.
- 문제를 누르면 해당 문장·사진·입력칸으로 이동한다. 이유, 현재값, 요구 조건, 해결 버튼을 함께 제공한다.
- 예: 본문 1,114자 · 최소 2,000자보다 886자 부족 → 경험 추가 / 이 부분 늘리기.
- 본문·광고 표시·태그 등 실제 검사 범위와 계산 기준을 일치시킨다. 근거 없는 완성도 점수는 만들지 않는다.
- 네이버·티스토리는 편집기로 옮기기, Instagram·Threads는 게시하기로 행동 이름을 구분한다.
- 전달 도우미는 준비→글→사진→서식→확인 중 실제 단계를 보여 준다. 부분 실패 시 남은 내용과 다음 행동을 안내하고 전체를 자동 재전송하지 않는다.
- 블로그에 입력된 상태를 게시 완료로 표시하지 않는다. 최종 발행 후 사용자가 게시물 주소를 기록할 수 있게 한다.
- 미리보기는 지원하는 서식의 예상 모습이다. 게시 플랫폼·블로그 스킨에 따른 차이가 있으므로 폰트와 배치를 완전히 동일하게 보장하지 않는다. 지원되지 않는 서식은 전달 전에 알린다.

## 5. 기능 우선순위

### 1순위: 먼저 만들 기본 경험

A. 단계별 작업 공간과 선택 항목 정리
- 기존 기능을 없애기보다 적절한 단계·맥락으로 옮긴다.
- 여러 모달을 연속으로 띄우는 흐름 대신 한 작업 공간에서 진행한다.
- 초보자는 기본 설정으로 완성하고 자주 쓰는 사용자는 마지막 설정으로 빠르게 시작한다.

B. 사진과 글을 함께 고치는 블록 편집기
- 문단·사진 순서를 직접 바꾸고 사진을 교체해도 설명 연결이 유지되게 한다.
- 사진 식별자는 표시 순번과 분리한다. 원본·채널별 잘라낸 결과도 구분한다.
- 기존 원고 변환은 원본을 보존하고 변환 전후 텍스트·사진 순서를 대조한다.
- 확장에 전달하는 결과도 같은 문서 구조에서 생성한다. 앱 미리보기만 바뀌고 전달 결과가 어긋나지 않게 한다.

C. 체험단 안내 정리와 문제 바로 고치기
- 업체 안내문에서 키워드·횟수·분량·사진·태그·필수 문구를 조건 카드로 제안한다.
- 원문 위치와 추출 근거를 확인하고 사용자가 확정한 조건만 검사 기준으로 삼는다.
- 날짜·가격·금지 표현·중복 조건·서로 모순되는 길이 조건을 구분한다.
- 업체 메모를 실제 방문 경험으로 바꾸지 않는다. 제공 표시도 사용자가 받은 내용으로 확인한다.
- 지도·특정 배너·외부 편집기 조작 등 자동 확인이 어려운 조건은 직접 확인 항목으로 남긴다.
- 최소 분량 미달은 기존의 제한된 보완을 유지하되, 자료가 부족하면 필요한 경험을 질문한다. 같은 말을 늘려 쓰거나 사실을 지어내서 통과시키지 않는다.

### 2순위: 결과 품질과 편집 제어

D. 부분 수정과 내 말투
- 기본 말투는 샘플 문장이 있는 4~6개 카드로 정리하고 자세한 선택은 더 보기에 둔다.
- 내 글 예시에서 선호하는 종결어미·문장 길이·이모지·피할 표현을 제안하고 저장 전 확인받는다.
- 블로그·Instagram·Threads마다 말투를 저장할 수 있게 한다. 젊은 여성 대상이라는 이유로 반말·과한 유행어·이모지를 일괄 강제하지 않는다.
- 영어는 직역보다 자연스러운 원고를 만들되 이름·숫자·필수 문구·확인된 경험을 보호한다.
- 제목 후보는 필요할 때만 3개 제안하고 사용자가 선택한다.

E. 채널별 편집 경험
- 블로그: 문단 사이 사진, 줄바꿈·정렬·지원 폰트 확인.
- Instagram: 작은 썸네일 순서, 첫 장, 슬라이드 미리보기, 잘리는 영역. 채널별 선택 사진과 원본을 분리하고 원본을 보존한다.
- Threads: 짧은 도입과 대화 흐름, 본문·사진 개별 선택. 과한 맞팔 유도나 실제 하지 않은 활동·약속을 만들지 않는다.
- 검토한 블로그 원고를 다른 채널에 활용하는 선택지를 제공하되 수정본을 자동 덮어쓰지 않는다. 원래 메모에서 새로 만들기와 현재 검토본 활용을 구분한다.
- 정보 출처는 필요할 때 내부 확인 패널에서 보여 주고 게시 본문에 참고 링크를 자동 나열하지 않는다. 사용자가 명시한 필수 링크는 별도 확인한다.

### 3순위: 반복 사용을 편하게

F. 내 글과 다시 쓰기
- 한 카드에 이야기 제목·대표 사진·최근 수정·채널별 작성/확인/전달 상태를 표시한다.
- 계속 쓰던 글을 첫 화면에서 바로 연다. 기존 검색을 확장해 장소·상태·채널로 찾는다.
- 체험단 조건·단골 업체 정보·자주 쓰는 태그 묶음을 재사용한다. 제공 내용과 날짜 등 달라질 수 있는 값은 재확인한다.
- 사진·메모만 글감으로 보관하고 나중에 원고를 만든다.
- 필요성이 확인되면 마감일 중심의 간단한 보기와 작성 예정일을 추가한다. 예약 작성 계획과 실제 자동 발행을 혼동시키지 않는다.

## 6. 시각 디자인 기준

방향: 사진과 원고가 주인공인 차분한 편집 작업실. 현재 Mellow 브랜드를 발전시키고 색을 많이 늘리기보다 간격·위계·읽기 편함으로 세련되게 만든다.

- 따뜻한 중립 배경 + 저채도 라벤더 한 가지 강조색. 사진 영역은 필터·반전 없이 원본 유지.
- 주요 입력·본문 15~16px를 출발점으로 검증하고 보조 문구도 읽기 쉬운 크기를 유지한다. 감성적인 작은 글씨로 핵심 안내를 대신하지 않는다.
- 일관된 간격, 버튼 크기, 모서리, 아이콘 세트를 사용한다. 사진·원고 바깥의 장식은 절제한다.
- 색만으로 선택·성공·문제를 표현하지 않는다. 글자·아이콘·상태 라벨을 함께 제공한다.
- 라이트·다크를 같은 토큰 체계로 만들고 실제 배경에서 대비를 확인한다. 본문 일반 텍스트 4.5:1, 큰 텍스트와 주요 컨트롤 3:1을 검수 목표로 삼는다.
- 사진 이동·저장·완료에 짧은 시각 반응을 제공하되 움직임 줄이기를 따른다.
- 데스크톱은 편집 중심 + 선택 보조 패널, 작은 화면은 단일 작업과 하단 패널. 드래그만으로 가능한 작업을 만들지 않는다.
- 복잡한 첫 사용 투어보다 샘플 글 한 편과 맥락에 맞는 짧은 도움말을 제공한다. 샘플은 실제 사용자 글과 분리한다.
- 개발 용어는 상세 진단 안에 두고 기본 오류는 원인·영향·다음 행동을 짧게 설명한다.

## 8. 실제 사용자 검증

아래 수치는 관측 결과가 아니라 첫 검증 목표다. 대표 사용자 약 5명으로 문제를 찾고 수정한 뒤 다시 확인한다.
- 도움 없이 새 글 시작·채널 선택·사진 추가·초안 확인·수정·전달의 핵심 작업을 5명 중 4명 이상 완료.
- 작성 중 새로고침, 뒤로 이동, 채널 변경 후 사용자 입력이 보존됨.
- 반복 입력 횟수, 불필요한 전체 재생성 횟수, 원고를 직접 고친 문단 수, 막힌 지점을 전후 비교.
- 사용자가 현재 선택한 채널과 실제 게시 여부를 정확히 설명할 수 있는지 확인.

대표 시나리오:
1. 사진 3장과 메모만으로 일상 블로그 한 편 만들기.
2. 업체 안내에서 2,000자·키워드·사진·광고 표시 조건을 확인하고 부족한 경험을 추가해 해결.
3. 사진을 중간으로 옮기고 교체한 뒤 네이버·티스토리 전달 결과 확인.
4. 한 문단만 자연스럽게 고치고 비교·취소·되돌리기.
5. 검토한 한국어 블로그를 영어 Instagram 원고로 추가하되 원본 보존.
6. Threads 문체를 바꿔도 Instagram 원고와 연결 선택이 바뀌지 않음.
7. 전달 중 사진 실패 후 이미 들어간 글을 중복 입력하지 않고 다음 행동 확인.
8. 작은 화면·키보드·다크 모드에서 필수 정보와 주요 행동 사용.

## 9. 이번 단계에 늘리지 않을 것

새 플랫폼 확대, 영상·릴스 제작, AI 이미지 생성, 복잡한 분석 대시보드, 팀 협업은 핵심 작성 경험이 안정된 뒤 필요성을 판단한다.
작성 화면에는 모델·토큰·소액 이용료·이용 내역을 다시 노출하지 않는다. 선택한 채널만 생성하고 단순 서식 변경은 로컬 처리하며, 검색은 선택 동작으로 유지한다.

초기 개발은 작성 흐름부터 블록 편집기와 체험단 조건으로 연결했다. 현재는 위 상태표의 범위를 구현했으며, 추가 기능 확대보다 현장 검증을 우선한다.

### E 구현 · 채널별 편집 경험

채널별 사진 선택·순서·첫 장·Instagram 프레임/부분 잘림 미리보기·Threads 사진 포함을 추가했습니다. 원본과 블로그 문서는 보존하며 실제 가공 결과와 미리보기에 같은 렌더러를 사용합니다. 공개 연결은 미리보기에 사용하지 않습니다.
확인한 블로그를 별도의 Instagram/Threads 제안으로 활용하는 흐름은 기존 메모에서 새로 만들기와 분리했습니다. 언어 선택·명시적인 원본 확인·전후 비교·조건 검사·사용자 적용을 거치며 취소와 되돌리기를 제공합니다. 기능 구현 검증과 실제 사용자/실계정 검증은 구분합니다.
다음 후보는 F 내 글과 다시 쓰기입니다. 이야기 카드의 채널별 상태·대표 사진·최근 수정, 이어 쓰기, 조건/업체/태그 재사용을 다루되 새 입력이 필요한 날짜·제공 내역을 재확인하는 방향입니다.


### F 구현 · 내 글과 다시 쓰기

이야기 카드의 채널별 작성/사용자 확인/편집기 입력/발행 기록, 첫 사진·최근 수정·검색/필터/페이지, 즐겨찾기·이름·정리/복구를 구현했습니다. 글감으로만 보관하고 최근 작업에서 직접 이어 쓰며, 미저장 이동에는 저장·계속 쓰기·저장하지 않고 이동을 구분합니다.
업체·장소·태그·구조화된 반복 미션의 저장/부분 재사용을 추가했습니다. 주소와 조건은 매번 확인하고 원고·사진·경험·제공 내역·기한·필수 문구·과거 확인 상태는 복사하지 않습니다. 선택 전후 비교와 필드별 되돌리기로 기존 작업을 보존합니다.
A~F의 계획된 핵심 기능 구현과 로컬 회귀 검증을 연결했습니다. 다음 검증은 실제 처음 사용자 관찰, 실계정 편집기/게시 결과, 중단·실패·복구의 사용성입니다. 서비스 운영·계정 분리·결제 준비와 유료 서비스 완성을 동일하게 취급하지 않습니다.


### G 구현 · 처음 사용하기와 중단 후 복구

선택적 도움말·격리된 체험 예시·쉬운 저장/전달 안내, 연결 끊김 후 행동 카드와 텍스트 보관, 복사 권한 실패 시 대안을 추가했습니다. 요청 번호를 받은 전체 글 생성은 같은 탭에서 기존 결과를 조회하며 자동 재요청하지 않습니다. 완료 결과를 별도의 새 이야기로 불러오고 현재 미저장 원고·타 채널·확인 상태를 보호합니다. 앱 재시작 등으로 결과가 없으면 사용한 메모를 복구하는 한계를 명시합니다.

다음 단계는 기능 수 확대보다 실사용 검증에 둡니다. 처음 사용하는 사용자의 준비→수정→확인→전달 관찰, 실제 네이버/티스토리 편집기와 SNS 게시 결과 비교, 사진 많은 원고·협찬 조건·영문 원고·중단 후 복구를 포함한 시범 사용에서 발견된 불편을 우선 보완합니다. 계정 분리·결제·운영 준비는 여전히 별도의 필수 작업입니다.


### H 구현 · 마지막 전달의 확신

글/사진/언어/블로그 요청 서식/대상 주소를 전달 직전 한곳에서 확인합니다. 사진 손상과 저장 버전 변경을 막고 취소 시 전달/발행하지 않습니다. 작업이 늦게 실행되더라도 당시 확인한 원고의 독립 복사본으로 진행합니다. 실제 확장 로딩과 모의 네이버/티스토리 입력·서식·기록 복구까지 회귀를 확장했습니다.

기능 구현만으로 실제 사용자와 플랫폼 검증을 대체하지 않습니다. 다음 우선순위는 실계정에서 네이버/티스토리의 글·사진·서식 및 SNS 게시 결과를 비교하고, 초심자가 도움 없이 한 편을 완성하는 과정을 관찰해 수정하는 것입니다. 기존 원고를 몰래 편집하거나 테스트 공개 게시물을 자동으로 올리지 않습니다.


### I 구현 · 직접 발행한 게시물 주소와 마무리

원래 4절의 마지막 전달 계획에 있던 ‘최종 발행 후 게시물 주소 기록’을 구현했다. 네이버/티스토리의 저장 원고와 주소를 사용자가 직접 확인해 연결한다. 주소 형식·채널/블로그·저장 버전을 검사하고, 추적 파라미터를 뺀 공개 게시물 주소를 보관한다. 주소를 서버에서 열거나 게시 내용을 자동 검증하지 않는다.

내 글에서 실제 게시물을 열고, 게시 기록에서 SNS API 기록과 직접 확인한 블로그 기록을 구분한다. 원고 변경 시 이전 발행본으로 표시하며 기록만 정리/복구할 수 있다. 실제 게시물·원고 삭제나 새 공개 발행을 하지 않는다. 이로써 이 문서의 핵심 기능 개발 흐름을 발행 이후까지 연결했다. 미완료 검증과 별도 운영 과제는 상단 표 및 8절을 따른다.
