# Mellow Studio · Content Studio

사진과 짧은 메모로 블로그 글과 인스타그램 캡션을 만드는 개인용 로컬 앱입니다.
네이버 입력 도우미 1.6.0과 작성 단계·미리보기·페이지 디자인 개선이 포함돼 있습니다.

## 집에서 개발 이어하기

Windows, Python 3.12 이상, Git, Chrome을 준비합니다. PowerShell에서 실행하세요.

    cd D:\dev
    git clone https://github.com/baekseungho/content-studio.git
    cd content-studio
    python -m venv .venv
    .\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
    Copy-Item .env.example .env
    notepad .env
    .\start.cmd

이미 클론했다면 해당 폴더에서 git pull로 최신 코드를 받습니다.
.env가 이미 있으면 복사 명령을 생략하고 기존 설정을 유지합니다.
브라우저 주소는 http://127.0.0.1:8787 입니다.

requirements-lock.txt는 회사에서 검증한 프로젝트 의존성만 고정한 파일입니다.
requirements.txt는 허용 버전 범위를 기록합니다. 가상환경은 컴퓨터마다 새로 만듭니다.

## 로컬 설정

.env.example에는 빈 예시 항목만 들어 있습니다. 실제 값은 각 컴퓨터의 .env에 입력합니다.

| 항목 | 용도 |
| --- | --- |
| OPENAI_API_KEY | 사진 분석·글 생성 |
| OPENAI_MODEL | 사진 분석 모델. 기본 gpt-5.4-mini |
| OPENAI_EDIT_MODEL | 부분 수정·제목 추천 전용. 미설정 시 OPENAI_MODEL 사용 |
| OPENAI_WRITING_MODEL | 선택한 원고의 문장 다듬기 모델. 기본 gpt-5.4 |
| OPENAI_PLACE_MODEL | 장소 후보 검색용 경량 모델. 기본 gpt-5.4-nano |
| NAVER_BLOG_ID | blog.naver.com/ 뒤의 블로그 아이디 |
| INSTAGRAM_ACCOUNT_ID | 인스타그램 프로페셔널 계정의 숫자 ID |
| INSTAGRAM_ACCESS_TOKEN | 해당 계정의 발행 권한이 있는 토큰 |
| INSTAGRAM_LOGIN_TYPE | auto / unified / instagram |
| PUBLIC_MEDIA_BASE_URL | 고정 사진 HTTPS 서버 주소. 임시 연결 사용 시 비워 둠 |

키가 없어도 직접 글쓰기·사진 업로드·미리보기·초안 보관·HTML 내보내기는 사용할 수 있습니다.
설정을 바꾸면 앱을 종료한 뒤 start.cmd로 다시 실행합니다.

## 네이버 연결 · 처음 한 번

1. 평소 네이버에 로그인하는 Chrome에서 chrome://extensions를 엽니다.
2. 개발자 모드 → 압축해제된 확장 프로그램을 로드 → 이 저장소의 chrome-extension 폴더를 선택합니다.
3. 확장 버전 1.6.0을 확인하고 도구 모음에 고정합니다.
4. Mellow 확장 아이콘에서 앱과 연결하기를 누릅니다.
5. 사진·메모 → 글 만들기 → 미리보기 → 블로그로 옮기기 순서로 사용합니다.

프로젝트 폴더가 바뀌었다면 Chrome에 등록된 확장도 새 chrome-extension 경로로 다시 등록하고 앱과 연결합니다.

로그인과 추가 인증은 네이버에서 직접 합니다. 마지막 발행도 네이버에서 누릅니다.
기존 내용이 있는 편집기는 덮어쓰지 않습니다. 같은 초안 재시험 옵션과 전달 코드는 도우미 옵션 안에 있습니다.
자세한 입력·서식 진단 방법은 [확장 설명서](chrome-extension/README.md)를 확인하세요.
기존 별도 자동화 브라우저 방식은 비활성화되어 있습니다.

## 인스타그램 사진 연결

Business 또는 Creator 계정과 Meta 앱의 발행 권한이 필요합니다.
통합 로그인(SUAT)·Facebook Login은 unified, Instagram Login은 instagram 방식으로 처리합니다. auto는 알려진 접두어만 참고하며, 접두어를 알 수 없는 유효한 통합 로그인 토큰도 있으므로 자동 구분이 안 되면 발급 방식에 맞춰 명시하세요. 토큰 형식만으로 유효·만료 여부를 판단하지 않습니다.
앱의 연결 설정에서 실제 토큰·계정 연결을 확인합니다.

고정 사진 서버가 없다면 Windows 64-bit용 cloudflared를 [Cloudflare 공식 다운로드](https://developers.cloudflare.com/tunnel/downloads/)에서 받아 tools/cloudflared.exe로 저장합니다.
직접 실행 파일은 Git에 포함하지 않습니다. 회사에서는 2026.11.0으로 확인했습니다.
앱의 연결 설정에서 사진 전용 임시 연결을 켭니다. 설치만으로 연결이 시작되지는 않습니다.
사진 연결은 발행용으로 허용된 JPEG 경로만 제공하며 앱 화면·API·원본 사진은 제공하지 않습니다.
인스타그램은 앱에서 발행을 확인하면 실제 계정에 게시됩니다.

## Git에 포함되지 않는 파일

- .env 및 개인 설정: 집 컴퓨터에서 별도 설정
- data/: 사진, SQLite 초안, 발행 기록, 로그인 프로필, 진단 결과
- .venv/: 컴퓨터별 Python 가상환경
- tools/*.exe, tools/*.zip: 설치 도구와 생성한 배포 파일

코드만 GitHub로 동기화됩니다. 회사의 사진·초안까지 이어서 쓰려면 앱을 종료한 상태에서 로컬 데이터와 설정을 별도로 옮깁니다.
API 키·토큰·로그인 프로필은 저장소에 커밋하지 않습니다.
글꼴의 출처와 라이선스는 static/fonts/NOTICE.txt와 OFL.txt에 있습니다.

이어서 수정할 때는 [개발 메모](docs/DEVELOPMENT.md)와 [변경 기록](CHANGES.md)을 먼저 확인하면 됩니다.

### 티스토리로 옮기기
확장 관리에서 도우미를 새로고침해 1.6.0을 확인합니다. 티스토리 탭에서 https://내이름.tistory.com 주소를 입력하고 글을 옮깁니다. 처음에는 직접 로그인한 뒤 빈 기본 편집기에서 도우미의 준비한 글 가져오기를 누릅니다. 티스토리 원고는 별도로 보관하며 마지막 발행은 직접 누릅니다. 티스토리는 나눔명조(감성 후기) 또는 나눔고딕(정보글)·15px와 선택한 정렬을 사용합니다. HTML·마크다운 모드는 지원하지 않습니다. 사진 업로드나 입력이 중단되면 남아 있는 내용을 먼저 확인하고 진단 결과를 복사해 주세요. 재현 테스트는 실제 계정 검증과 구분됩니다.

## Threads와 영어 글쓰기

- 언어에서 한국어 또는 English를 고른 뒤 글 만들기를 누릅니다. 메모는 한국어로 적어도 됩니다. 기존 글은 언어 선택만으로 번역되거나 덮어써지지 않습니다.
- 플랫폼 선택 창에서 고른 곳의 글만 같은 사실을 바탕으로 작성합니다. 영어는 원어민 대화체 편집 지침으로 별도 다듬기를 거칩니다. 기존 모델 설정을 사용하며 영어 선택 시 글 다듬기 단계가 실행됩니다.
- Threads 탭에서 친구에게 툭(반말), 편한 존댓말, 짧은 위트 중 말투를 고릅니다. 다음 글 만들기에 적용되며 광고 표시를 포함해 500자 이내입니다.
- Threads 전용 계정을 연결하면 앱에서 글·사진을 발행할 수 있습니다. 발행 전 공개 확인을 받습니다. 직접 작성 화면에서 이어 쓰기 기능도 보조 버튼으로 유지합니다. 인스타그램 토큰은 재사용하지 않습니다. 연결 순서는 [Threads 연결 안내](docs/THREADS_SETUP.md)를 참고하세요.
- 영어 생성은 필수 메모의 영어 표현과 영어 광고 표시를 사용합니다. 생성 뒤 한국어 필수 메모를 바꾸면 영어 글을 다시 만들어 반영해 주세요. 원문과 번역의 연결이 달라지면 인스타그램 발행을 막고 안내합니다.
- 보관함에는 언어·Threads 말투·Threads 본문도 함께 보관됩니다. 기존 초안에는 한국어와 빈 Threads 글이 기본값으로 적용됩니다.

규격 참고: [Meta의 일반 게시물·텍스트 첨부 안내](https://about.fb.com/news/2025/09/attach-text-threads-posts-share-longer-perspectives/), [Threads Web Intents](https://developers.facebook.com/documentation/threads/threads-web-intents).

Threads 발행: 글만, 사진 한 장, 여러 사진을 지원합니다. 발행 기록과 중복 방지는 인스타그램과 분리됩니다. 사진 공개 연결은 기존 연결을 공유하며 -ig.jpg 파생 사진만 사용합니다. 응답이 불명확하면 계정 확인 전 재발행을 차단합니다.

## 체험단·협찬 후기

상단에서 체험단·협찬 후기를 고르고 업체 안내문을 붙여넣습니다. 실제 경험은 기존 메모에 따로 적습니다. 자동으로 확인할 제목·본문 키워드, 필수 문구, 최소 글자 수·사진 수는 해당 칸에 입력합니다. 광고·제공 표시도 선택합니다. 글 만들기와 저장 후 업체 미션 카드에서 누락된 항목을 확인하고, 미션 수정으로 입력칸을 다시 엽니다.

키워드 횟수는 해시태그를 제외한 본문에서 확인합니다. 공백·줄바꿈은 한국어 키워드 비교에서 무시합니다. 글자 수는 공백·사진 위치 표시·해시태그를 제외합니다. 최소 사진은 현재 앱의 최대 10장 범위에서 입력합니다. 업체 안내문의 자연어 조건 전체를 자동 검증하는 기능은 아닙니다.

블로그 해시태그는 입력한 순서로 본문 끝에 반영합니다. 네이버 발행창의 검색 태그는 태그 복사 후 직접 넣고 확인합니다. 지도·구매 링크·배너 등은 네이버에서 직접 추가합니다. 미충족 미션이 있으면 앱의 네이버·티스토리 전달을 막고 수정할 항목을 안내합니다. 직접 경험과 충돌하는 업체 요청을 허구로 채우지 않습니다. 체험단 모드를 끄면 이전 업체 입력은 보관되지만 다음 글의 조건으로 사용하지 않습니다.

## Threads 소통 말투

편한 반말과 짧은 줄, 작은 취향·경험을 중심으로 씁니다. 스친 말투 살짝을 켜면 스친·스친들 같은 호칭을 필요할 때 사용하고, 먼저 인사하고 소통하고 싶어요를 켜면 교류 인사를 넣을 수 있습니다. 스하리·반하리 등은 사용자가 직접 의향을 적었을 때 문맥에 맞게 반영합니다. 실제로 하지 않은 맞팔·하트·리포스트 완료나 개인 신상·육아 경험을 만들지 않습니다. 자동 팔로우·하트·리포스트 기능은 수행하지 않습니다. 영어는 한국식 신조어의 음역 대신 자연스러운 영어 대화체를 유지합니다.


### 장소를 선택해 동명 업체 구분하기

‘어디에 다녀왔나요?’는 선택 사항입니다. 장소 이름과 지역·지점으로 검색한 뒤 이름과 주소를 보고 선택하세요. 찾는 곳이 없으면 이름과 전체 주소를 직접 입력할 수 있습니다. 선택한 장소와 정보 검색 설정은 글과 함께 보관됩니다. 장소를 바꿔도 이미 만든 글은 자동으로 바뀌지 않으므로 새로 생성해 주세요.

‘필요한 정보도 찾아서 담기’를 켜면 선택한 이름·전체 주소를 기준으로 별도 검색합니다. 출처에서 관찰한 이름·주소가 선택한 장소와 맞고 실제 검색 출처에 포함된 정보만 작성 단계에 넘깁니다. 불확실한 정보는 제외하고 그 이유를 결과 안내에 표시합니다. 이 검사는 웹 정보의 진실성이나 최신성을 보장하지 않습니다. 영업시간·가격·주차와 체험단 업체 안내는 발행 전에 확인하세요. 장소 선택이나 정보 검색을 하지 않아도 기존처럼 메모·사진으로 작성할 수 있습니다.

기본 장소 후보 검색은 기존 OpenAI 키를 사용하며 소액의 검색 비용이 추가됩니다. 선택적으로 `.env`에 `NAVER_SEARCH_CLIENT_ID`, `NAVER_SEARCH_CLIENT_SECRET`을 넣으면 네이버 지역 검색 목록을 사용합니다. Naver Cloud API HUB 키는 `NAVER_SEARCH_PROVIDER=ncp`(기본값), 기존 Naver Developers 검색 API 키는 `naver`로 지정하세요. 설정 변경 후 앱을 다시 실행하세요. 이 키는 네이버 검색용이며 블로그 자동 발행 권한이 아닙니다.

공식 API 안내: https://api.ncloud-docs.com/docs/naver-api-hub-search-local · 기존 검색 API: https://developers.naver.com/docs/serviceapi/search/local/local.md


### 필요한 플랫폼만 만들기

‘예쁘게 글 만들기’를 누르면 네이버 블로그·인스타그램·티스토리·Threads 중 필요한 곳을 고르는 창이 열립니다. 기본은 현재 탭 한 곳만 선택되며 여러 곳도 고를 수 있습니다. 선택하지 않은 글은 작성·다듬기 모델에 보내거나 새로 만들지 않습니다. 창을 닫으면 AI 요청이 발생하지 않습니다. 이미 원고가 있는 플랫폼을 선택하면 그 플랫폼만 다시 작성합니다.

미작성 플랫폼 탭을 누르면 그곳의 글만 추가 작성할지 고를 수 있습니다. 취소해도 기존 원고는 그대로이며 ‘직접 쓸게요’도 가능합니다. 추가 작성 실패 시 기존 글을 유지합니다. 네이버와 티스토리 원고는 이제 별도로 저장합니다. 이전 버전에서 공통으로 썼던 원고는 처음 열 때 양쪽에서 볼 수 있게 호환하고, 새로 생성할 때에는 선택한 원고만 바꿉니다.

장소 후보 찾기는 `OPENAI_PLACE_MODEL`(기본 `gpt-5.4-nano`)로 분리했습니다. 장소 상세정보의 조사·출처/주소 대조는 기존 모델과 기준을 유지합니다. 선택한 장소와 메모·필수 사실·업체 안내문이 모두 같은 추가 작성 요청은 서버에서 확인한 장소 조사 결과를 최대 15분간 재사용합니다. 입력이 바뀌거나 만료되면 새로 조사하며 앱을 다시 실행하면 캐시는 사라집니다. 네이버 지역 검색 키가 있으면 후보 목록은 기존처럼 해당 API를 사용합니다.


### 체험단 글자 수와 수정 안내
체험단 입력란의 ‘본문 길이 조건’에서 최소(이상), 최대(이내), 공백 포함을 고릅니다. 한쪽만 제한하려면 다른 값은 0으로 두세요. 제목·태그·사진 위치 표시는 제외하며 줄바꿈은 포함하지 않습니다. 원고에 붙는 제공 안내는 본문에 포함됩니다. 조건을 맞추기 위한 허구·반복 문장은 만들지 않으므로 부족한 경험이나 과한 분량은 점검에서 알려 줍니다.

옮기기를 막는 항목은 입력칸에 이유가 표시되고, 점검 카드의 ‘조건 수정’ 또는 ‘제목/본문 수정’으로 이동할 수 있습니다. 수정하면 로컬 점검만 다시 하므로 AI 비용이 들지 않습니다. 같은 단어를 제목·본문 양쪽에 쓰는 것은 정상입니다.

영문으로 새로 만들면 선택한 플랫폼의 원고만 새로 씁니다. 한국어 태그는 영문 원고에 자동으로 붙이지 않습니다. 체험단의 정확 일치 조건이 한국어인 경우 자동 번역해 충족으로 처리하지 않으므로, 업체와 확인한 영문 키워드/문구/업체명/태그를 입력하거나 한국어로 작성해 주세요.


### 글의 줄바꿈과 호흡
블로그 탭에서 ‘글에도, 나다운 호흡을’을 펼치세요. 내 줄바꿈(유지), 짧은 메모(약 20자·2줄), 편안한 호흡(28자·3줄), 차분한 리뷰(40자·5줄)를 고르거나 슬라이더로 조절합니다. 원래 문단을 보존하면서 긴 문단을 선택한 줄 수마다 나눕니다. 영어는 줄 길이를 두 배로 잡으며 단어를 자르지 않습니다. 긴 단어·사진 위치·소제목·태그·정보 목록은 보호하므로 실제 길이는 예시와 다를 수 있습니다.
설정은 네이버/티스토리별로 저장되어 새 글에 자동 반영됩니다. 기존 글은 ‘지금 글에 적용’으로 바뀌며 AI를 호출하지 않습니다. 적용 전 줄바꿈으로 되돌릴 수 있고, 이후 직접 문장을 고쳤다면 이전 기록으로 덮어쓰지 못하도록 보호합니다. 사진이 변경되면 되돌리기 기록도 초기화합니다. 줄바꿈은 원고에 저장해 기존 도우미로 전달하므로 확장 업데이트가 필요하지 않습니다. 최종 편집기 폭·글꼴에 따라 화면에서 추가로 줄이 감길 수 있습니다.


### 정리된 작성 화면
먼저 글 종류를 고른 뒤 사진과 메모를 넣습니다. 필요한 항목만 ‘장소·추가 메모’ 또는 ‘말투·언어·글 꾸미기’에서 펼치세요. 체험단을 고르면 별도의 미션 카드가 나타나며, 제공 유형/업체 안내와 키워드·태그·분량 조건을 설정할 수 있습니다. 접힌 제목에서도 선택한 주요 설정을 확인할 수 있습니다.
완성한 글은 오른쪽에서 확인하고 저장·복사·옮기기를 진행합니다. 태그 복사와 파일 저장은 ‘추가 기능’에 있습니다. 플랫폼별 연결/말투 설정과 체험단 점검 목록은 필요할 때 펼칠 수 있으며, 옮기기를 막는 오류 이유·수정 버튼은 접지 않고 표시됩니다. 이용료와 토큰 이용 내역은 작성 화면에 표시하지 않습니다.


### 글자 수가 부족할 때
생성과 문체 다듬기가 끝나면 동일한 문자 수 기준으로 검사하고, 분량이 맞지 않는 블로그만 자동으로 한 번 보완합니다. 충분한 원고를 다듬다가 다시 짧아지면 원래 길이를 유지합니다. 보완해도 조건을 못 맞추면 ‘완성’ 대신 남은 분량 조건을 안내합니다.
기존 초안도 ‘발행 전 점검’에서 ‘이 초안에서 분량 보완’을 누르면 이어서 보완할 수 있습니다. 이 작업은 글쓰기 요청이며 다른 플랫폼이나 사진 분석을 다시 실행하지 않습니다. 메뉴·이용 과정·구체적인 장단점·사진 설명 등 실제 경험 메모를 더하면 도움이 됩니다. 최대 분량 초과 시에는 같은 버튼으로 핵심을 유지하며 줄입니다. 정확한 최신 사실과 업체 조건은 발행 전 확인하세요.


## 블로그 생성 분량 상한 (2026-11-18)
- 본문 최소·최대 조건은 각각 0~5,000자의 정수만 받습니다. UI와 서버에서 확인하며, 초과 조건은 AI 요청 전에 거절합니다.
- 최대 0은 기본 상한 5,000자를 뜻합니다. 체험단이 아닌 글에도 상한을 적용하며, 제목·태그·사진 표시는 제외하고 기존 공백 포함 선택 기준으로 셉니다. 상한은 목표 분량이 아니므로 짧은 메모를 무조건 5,000자로 늘리지 않습니다.
- 생성·말투 다듬기·분량 보완에 같은 상한을 전달하고 출력 토큰 예산도 제한합니다. 더 작은 최대치를 설정하면 블로그 출력 예산도 줄어듭니다. 각 AI 호출의 최대 출력 토큰은 24,000이며 자동 분량 보완은 최대 한 번입니다. 글자 수는 토큰 수나 비용과 일치하지 않습니다.
- 초과 원고는 임의로 잘라내지 않고 한 번 줄여 보완합니다. 그래도 넘으면 현재 분량·상한과 본문 수정/분량 보완을 표시합니다. 기존 저장 원고는 그대로 유지됩니다.


## 사용자 흐름·검토 편의 개선 (2026-11-18)
- 본문 하단의 글자 수와 분량 막대를 실제 점검 기준으로 통일했습니다. 블로그는 제목·태그·사진 표시를 제외하고 선택한 공백 기준으로 계산하며, 최소까지 부족한 수/상한 초과를 바로 표시합니다. Instagram·Threads는 이모지를 Python 서버와 같은 코드 포인트 기준으로 셉니다.

## 내부 동작·충돌 점검 (2026-11-18)

### 필요한 부분만 다듬기

‘글 수정’에서 문단 아래 **문단 다듬기**를 눌러 보세요. 문장을 선택하면 그 부분만 제안하고, 사진 설명도 따로 고칠 수 있어요. 수정 전후를 읽고 **이 부분에 적용**을 눌러야 원고가 바뀝니다. 제목의 **제목 추천**도 요청할 때만 후보 3개를 만들어요.

‘말투·언어·글 꾸미기’에서 채널과 말투 카드를 고르거나 **내 말투 만들기·저장**으로 예문과 취향을 기억할 수 있어요. 새로 만드는 글에만 적용하며 이미 만든 글은 자동으로 바뀌지 않아요. 원고를 선택해 **내 말투로** 요청하면 그 부분만 새 말투로 다듬습니다.

비교 화면의 직접 수정·조건 재검사·예문 말투 분석은 AI를 호출하지 않아요. AI 제안을 요청하면 한 번 호출하며, 창을 닫아도 이미 시작한 외부 작업 자체가 취소되지는 않아요. 뜻과 사실은 마지막으로 직접 읽어 주세요.


### 채널마다 사진을 다르게, 블로그는 다른 이야기로

Instagram·Threads 탭에서 **사진 고르기**를 눌러 그 채널에 올릴 사진만 고르세요. **사진 순서·첫 장·화면 맞춤**에서 순서를 바꾸고 첫 장을 정합니다. Instagram의 **화면 맞춤**은 전체를 보이거나 일부를 잘라 화면을 채웁니다. 원본과 다른 채널의 사진은 바뀌지 않아요. Threads에서 사진 포함을 끄면 골라 둔 사진을 보관하면서 글만 올려요.

**확인한 블로그에서 가져와 쓰기**는 이미 읽고 확인한 네이버·티스토리 블로그를 바탕으로 별도 SNS 글을 제안해요. 한국어·영어를 고르고 원본 확인을 체크한 뒤 요청하세요. 비교 화면에서 **새 채널 원고로 적용**해야 바뀌며 기존 사진 선택은 유지합니다. 메모에서 새로 만들기는 기존 글 만들기 버튼을 사용하세요.

사진 선택·순서·자르기·미리보기·조건 재검사는 AI를 사용하지 않아요. 새 SNS 원고 제안을 요청할 때만 텍스트 모델을 한 번 호출합니다. 미리보기는 공개되지 않고 실제 발행 요청 때 필요한 가공 사진만 사진 전용 연결에 제공해요. 실제 앱 화면의 장식이나 크기는 미리보기와 다를 수 있습니다.


### 내 글에서 이어 쓰고, 자주 쓰는 설정 기억하기

**사진·메모를 글감으로 보관**하면 아직 글을 만들지 않아도 저장할 수 있어요. 첫 화면의 최근 이야기나 **내 글**에서 다시 엽니다. 보관함에서 채널·작성 상태로 찾고 즐겨찾기나 이야기 이름을 정할 수 있어요. **목록 정리**는 삭제가 아니며 **정리한 이야기**에서 다시 꺼냅니다.

마지막 확인 화면의 **이 원고 확인했어요**는 지금 저장한 원고를 읽었다는 표시예요. 발행 완료와는 다릅니다. 글이나 사진을 바꾸면 다시 확인하며, 네이버·티스토리의 **편집기 입력 완료**도 최종 발행 여부는 직접 확인해야 해요.

**현재 설정 기억하기**에서 업체·장소, 태그, 체험단 조건을 저장하고 **저장한 설정 불러오기**로 필요한 항목만 고릅니다. 주소와 조건을 이번 글에도 쓸 수 있는지 확인하고 전후 비교 후 적용하세요. 글·사진·방문 경험·제공 내역·기한·정확한 필수 문구는 불러오지 않아요. 적용 후에는 준비 화면의 **불러오기 전 설정으로**로 되돌릴 수 있습니다.

저장·보관함·원고 확인·설정 재사용은 AI를 호출하지 않아요. 저장하지 않은 내용이 있을 때 다른 이야기로 이동하면 저장 여부를 먼저 선택합니다.


### 처음 사용하거나, 작업 중 연결이 끊겼을 때

오른쪽 위 **도움말**에서 준비·다듬기·옮기기를 확인하세요. **예시로 사용법 보기**는 별도 체험 화면이에요. 예시에서 글이나 사진 순서를 바꿔도 실제 작업에는 반영되지 않아요.

글 만들기 중 새로고침했다면 **이전 결과 확인**부터 눌러 주세요. 기존 요청의 진행 상황과 결과만 확인하며 새 글을 요청하지 않아요. 완료된 결과는 읽어 본 뒤 **새 이야기로 불러오기**로 가져옵니다. 현재 글을 수정 중이면 먼저 저장 여부를 고르세요. 사진과 조건도 함께 확인한 뒤 보관해 주세요.

이 기능은 요청 번호를 받은 같은 탭에서 사용할 수 있어요. 앱이 종료됐거나 결과 보관 시간이 지나면 완성 글을 찾지 못할 수 있어요. 이때는 요청에 쓴 메모만 새 글감으로 불러올 수 있습니다. 브라우저 탭/기록을 지우기 전 중요한 글은 **글 보관하기**로 저장해 주세요.

연결이 끊기면 **연결 확인**을 눌러 앱 상태를 확인할 수 있어요. 실패한 요청을 자동으로 재전송하지 않아요. 발행 중이었다면 계정에서 결과를 먼저 확인하세요. **현재 글 텍스트로 받기**는 앱 연결 없이도 가능하지만 사진은 포함하지 않아요. 자동 복사가 막히면 표시된 내용을 직접 선택해서 복사할 수 있습니다.


### 블로그로 옮기거나 SNS에 발행하기 전

마지막 버튼을 누르면 먼저 글을 보관하고 **최종 확인** 화면을 보여줘요. 실제 전달할 본문, 이번 채널에 선택한 사진 순서, 작성 언어를 읽어 주세요. 블로그는 주소·요청 정렬·글꼴도 표시해요. 사진을 읽을 수 없으면 먼저 수정해야 합니다.

**확인한 글·사진 옮기기**는 블로그 편집기에 입력하는 단계예요. 입력된 사진·글꼴·정렬을 직접 확인하고 최종 발행은 블로그에서 눌러 주세요. Instagram·Threads의 **확인한 내용 공개 발행**은 연결된 계정에 공개 게시해요. 계정 권한과 플랫폼의 실제 반영 여부는 발행 과정에서 확인합니다.

돌아가기·닫기·Esc는 전달과 발행을 취소해요. 다른 창에서 같은 원고가 바뀌었다면 현재 확인을 중단하고 최신 글을 다시 읽어 주세요. 현재 화면의 원고를 별도 이야기로 보관할 수도 있어요. 발행 요청이 시작된 뒤에는 당시 확인한 저장 원고로 진행합니다.


### 블로그에서 발행한 글 주소 남기기

네이버·티스토리에서 직접 발행한 뒤 마지막 확인 화면의 **발행한 글 주소 남기기**를 누르세요. 원고를 수정 중이면 먼저 실제 발행한 내용과 같은지 확인하고 보관해 주세요. 주소를 넣고 **주소 확인**을 누른 뒤 게시물을 직접 읽었다는 확인을 선택하면 기록합니다.

**내 글** 카드의 **게시물 열기**로 다시 열 수 있어요. 내 글 안의 **게시 기록**에서는 직접 확인한 블로그 기록과 SNS API 기록을 구분합니다. 원고를 바꾸면 이전 발행 주소로 표시하며, 기록만 정리하거나 다시 꺼낼 수 있어요. 실제 게시물이나 원고를 삭제하지 않아요.

주소 확인은 형식과 연결할 블로그를 검사합니다. 게시물을 자동으로 열어 내용이나 공개 상태를 검증하지는 않아요. 원고와 게시물이 같은지는 직접 확인해 주세요.
